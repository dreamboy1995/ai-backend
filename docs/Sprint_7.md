
## Sprint 7
这是整个项目从"工具"变成"员工"的分水岭。如果说前两个阶段是在教 AI"看懂代码"和"握稳笔杆"，那么 P3 阶段就是教 AI"独立做项目"。

Sprint 7 的核心是搭建 Agent 的"大脑"（Planner） 和 "躯干"（ReAct 执行框架），让 AI 能够把用户的模糊需求（如"做个博客网站"）自动拆解成任务清单，并一步步执行下去。


### 核心目标（S7）
任务规划与 Agent 骨架：后端实现基于 ReAct（Reasoning + Acting） 范式的 Agent 状态机；通过精心设计的 Prompt 工程实现 Planner（任务规划器），将自然语言需求拆解为结构化的 DAG 任务图；插件端上线 Builder 面板，将任务的"思维链"可视化呈现给用户。


### 👥 人员分工（S7 重点是 Agent 架构设计）
- 后端开发（1-2人）：Agent 状态机设计（LangGraph 或自研）、Planner 提示词工程、任务图数据结构定义、ReAct 循环骨架搭建（含模拟工具执行占位）。
- 插件开发（1人）：Builder 面板 UI（独立宽屏视图）、任务步骤进度条、勾选与状态轮询。

|后端	| 1. 编写 react_loop.py，实现主循环：`python<br> async def run_agent(session_id: str):<br> session = get_session(session_id)<br> while True:<br> step = get_next_runnable_step(session)<br> if not step:<br> break # 所有步骤完成或无可用步骤<br> # Step 1: Reason（思考）<br> prompt = build_step_prompt(session.user_goal, step, session.context)<br> action_json = await llm.invoke(prompt) # 返回 {"tool": "write_file", "params": {...}}<br> # Step 2: Act（行动）—— S7 先用模拟器（Mock）代替真实工具<br> observation = await mock_tool_executor(action_json)<br> # Step 3: Observe（观察）<br> mark_done(step.id, observation)<br> # 更新上下文，进入下一轮循环<br>`<br>2. 模拟工具执行器（Mock）：mock_tool_executor 不真的读写文件，而是返回硬编码的成功消息（如 "文件 main.py 创建成功（模拟）"），用于验证循环逻辑的通畅性。	 |启动 Agent，观察后端日志：循环依次处理步骤 1 → 步骤 2 → 步骤 3，每个步骤都经历了 Reason -> Act -> Observe 的完整生命周期，且日志中打印出模拟的执行结果。|

### 🔧 S7 关键技术预研与风险预警（研发必读）
| 风险点	                   | 应对方案                                                                                                                                                 |
|--------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------|
| Planner 输出不稳定	       | 同样的需求，模型每次生成的步骤数量可能波动很大。必须在 System Prompt 中给死 “步骤数范围（5-10步）”，并在解析 JSON 后校验数量，过少或过多则触发重新生成。 |
| ReAct 循环中的上下文爆炸	 | 每执行一步，observation 都会累积进 Prompt。必须为 Agent 设计 独立的记忆裁剪策略（比如只保留最近 3 步的完整观察结果，更早的只保留摘要）。                 |

模拟工具与真实工具的衔接	S7 的 Mock 工具返回假数据，但 S8 要换成真实的 MCP 工具。需要在代码层面做好 依赖注入（Dependency Injection），定义一个 ToolExecutor 抽象基类，S7 注入 MockToolExecutor，S8 只需替换为 MCPToolExecutor，上层循环代码无需修改。

用户中途关闭 VS Code	如果 Builder 执行到一半用户关了 VS Code，Agent 会话应该持久化在 Redis 中。下次打开插件时，检测到未完成的 Session，提示用户“有未完成的构建任务，是否继续？”。
