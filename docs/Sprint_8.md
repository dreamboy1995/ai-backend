
## Sprint 8 —— 真刀真枪的工具执行层
如果说 S7 是给 Agent 装上了“大脑”和“骨架”，那 S8 就是给它装上“手脚”。这个 Sprint 要把 S7 里的所有“模拟（Mock）”全部替换为真实操作：Agent 将真正地读写你的硬盘文件、执行终端命令、搜索代码，甚至帮你自动提交 Git。

这是 P3 阶段工程风险最高的 Sprint，因为涉及文件系统操作和进程管理，稍有不慎就可能搞乱用户代码。所以安全护栏（确认弹窗、沙箱、白名单）是本期的重中之重。

### 核心目标（S8）
MCP 协议工具落地与沙箱集成：基于 MCP（模型上下文协议） 标准封装文件读写、终端执行、代码搜索、Git 操作等工具集；在插件端集成终端输出流式查看器；引入轻量级沙箱（Docker）隔离 Agent 的执行环境，防止恶意操作。


### 👥 人员分工（S8 后端工程压力巨大）
- 后端开发（1-2人）：MCP 工具服务器实现（含 stdio/HTTP 适配）、命令拦截与白名单引擎、Docker 沙箱编排、进程生命周期管理。

- 插件开发（1人）：终端输出实时流式展示组件、危险命令确认弹窗、Git 自动提交的 Diff 预览。

### 📂 关键接口/数据结构变更（S8 新增）
1. 工具执行与确认接口
```typescript
// Agent 内部调用（后端内部）
POST /v1/tool/execute
Request: { session_id: string; tool_call: ToolCall }
Response: ToolResult

// 插件端调用（用户确认后）
POST /v1/tool/confirm
Request: { session_id: string; confirmation_id: string; action: 'allow' | 'deny' }
Response: { success: boolean; result?: ToolResult }
```

2. 终端日志流式接口（WebSocket 或 SSE）
```typescript
// 使用 WebSocket 路径
ws://localhost:3000/v1/agent/stream/{session_id}
// 消息格式
interface StreamMessage {
  type: 'stdout' | 'stderr' | 'system';
  content: string;  // 可能包含 ANSI 颜色码
  timestamp: string;
}
```

3. 插件端 GlobalState 新增安全设置
```typescript
interface GlobalState {
```

### 🔧 S8 关键技术预研与风险预警（研发必读）
| 风险点                         | 应对方案                                                                                                                                                                                                                           |
|--------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Docker 在 Windows/Mac 上性能差 | 	Windows 的 Docker Desktop 文件挂载 IO 较慢。建议在挂载时使用 :delegated 模式（-v /host/path:/workspace:delegated），牺牲一点一致性换性能。                                                                                         |
| 终端命令的交互式输入	           | Agent 执行 npm init 或 python 交互式命令会卡住。解决方案：Agent 执行命令时强制追加 --yes（npm）或 -c "代码"（Python），避开交互。若必须交互，则工具应返回 requires_interaction=True，由用户手动在真实终端完成，再告知 Agent 继续。 |
| 命令注入攻击	                   | 恶意用户可能写 Prompt “执行命令 hello; rm -rf /”。后端必须对 run_command 的参数进行 严格转义，最好使用 subprocess 的列表参数模式（["ls", "-la"]）而非字符串拼接，从根源杜绝注入。                                                  |
| 容器内访问宿主机 localhost	     | 如果 Agent 需要在容器内访问宿主机启动的服务（如数据库），Docker 默认无法访问。需要提供 --add-host host.docker.internal:host-gateway 参数，并让用户明确授权“允许访问宿主机网络”。                                                   |
| 大文件写入导致内存溢出	         | Agent 可能一次性写入 50MB 的文件。后端必须在 write_file 中 分块流式写入，而非 f.write(content) 一次性加载，避免 OOM。
