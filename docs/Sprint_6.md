
## Sprint 6
### 核心目标（S6）
这个 Sprint 完成后，你的产品将具备 “Cursor 级别的编辑体验”：用户可以直接在代码里圈选区域进行对话（Inline Chat），AI 给出的多文件修改建议会以清晰的 Diff 预览呈现，甚至能“猜到”用户下一步要改哪里（Cue 能力）。这是从“聊天机器人”进化为“结对编程搭档”的关键一跃。
编辑体验全面升级：实现 Ctrl+K 内嵌对话（Inline Chat）悬浮框；后端支持多文件结构化输出（强制模型返回 JSON 格式）；插件端实现专业级 Diff 预览面板（逐文件、逐行接受/拒绝）；实现基于启发式规则的编辑位置预测（Cue 能力雏形）。


### 👥 人员分工（S6 前端/编辑器交互压力较大）
- 插件开发（1-2人）：Inline Chat 悬浮 UI、Monaco Diff 编辑器集成、光标位置监听与 Cue 提示渲染、多文件 Diff 状态管理。
- 后端开发（1人）：Structured Output（JSON Mode）工程化、多文件编辑指令的 System Prompt 调优、Diff 生成辅助工具（计算变更行）。

### 📂 关键接口/数据结构变更（S6 新增）
1. Chat 请求体新增 `mode` 字段
```typescript
POST /v1/chat/completions
Request: {
  // ... 原有字段
  mode: 'chat' | 'inline' | 'builder';  // S6 新增 inline
  inline_selection?: {                  // inline 模式专用
    file_path: string;
    selected_text: string;
    start_line: number;
    end_line: number;
  };
  response_format?: { type: 'json_object' }; // S6 新增，强制结构化输出
}
```

2. SSE 流中的 Diff 元数据块
```typescript
// 在流结束前推送
data: {
  "type": "diff",
  "files": [
    {
      "path": "src/main.py",
      "old_content": "import os\nprint('hello')",
      "new_content": "import logging\nlogging.info('hello')",
      "diff": "--- a/src/main.py\n+++ b/src/main.py\n@@ -1,2 +1,2 @@\n-import os\n-print('hello')\n+import logging\n+logging.info('hello')"
    }
  ]
}
```

3. Cue 预测接口
```typescript
POST /v1/cue/suggest
Request: {
  file_path: string;
  modified_line: number;
  action: 'rename' | 'delete' | 'add_method';
  symbol_name: string;
}
Response: {
  suggestions: [
    { file_path: string, line: number, reason: '此函数调用了被改名的符号' }
  ];
}
```


### 🔧 S6 关键技术预研与风险预警（研发必读）
|风险点	|应对方案|
|---|---|
|JSON Mode 解析失败	|大模型即使加了 `response_format`，有时仍会在 JSON 前后加` ```json `标记。后端必须用正则 `/(\{.*\})/s` 提取纯净 JSON 体，并用 `json.loads` 包裹 `try-except`，失败时降级为纯文本。 |
|Diff 数据量过大撑爆 SSE	|如果用户要求修改 10 个文件，每个文件 500 行，JSON 内容可能达到数 MB。解决方案：后端开启 Gzip 压缩（`Content-Encoding: gzip`），且超过 3 个文件时，改用 分片传输（先返回文件列表元数据，再逐个文件推 Diff）。|
|Inline Chat 光标焦点丢失	|打开 Inline Chat 输入框后，用户的键盘焦点从编辑器移到输入框，可能导致选中文本的高亮消失。插件必须在打开输入框时 冻结 选区状态（保存一份快照），关闭输入框时恢复。|
|Cue 规则误报	|启发式规则必然有误报（推荐了不该推荐的位置）。必须在 UI 上做 弱视觉设计（灰色小点，而非亮色大按钮），并允许用户一键 “关闭所有 Cue 提示”（在设置面板加开关）。|
